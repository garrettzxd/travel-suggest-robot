# 统一接口响应格式与未登录跳转方案

## Summary

- 普通 REST 接口统一返回 `{ code, data, message }`，成功 `code=0`，失败使用集中管理的业务 code。
- 保留 HTTP 状态语义：400/401/404/409/500 等仍按原状态返回，前端以 body.code 做业务判断。
- `/api/chat` 成功路径保持现有 SSE 事件流；仅鉴权失败、参数校验失败、会话不存在等进入 SSE 前的普通 HTTP 响应使用统一格式。
- 未登录业务码使用 `10001`；前端任意接口识别到 `10001` 后清空登录态并自动跳转 `/login`。

## Key Changes

- 新增共享响应契约：`ApiResponse<T> = { code: number; data: T; message: string }`，以及前端可复用的未登录 code 常量 `10001`。
- server 层新增集中管理模块，统一维护业务 code、`ApiError`、成功响应 helper、错误响应 helper。
- server 路由改为通过统一 helper 返回；`logout/delete` 从 204 改为 200，并返回 `{ code: 0, data: {}, message: "" }`。
- server 应用层增加统一异常处理中间件，捕获 `ApiError` 和未知异常；`ctx.respond=false` 的 SSE 成功流不包装。
- frontend 合并 REST 请求解析逻辑，所有非 SSE JSON 请求先解析 `ApiResponse<T>`；`code === 10001` 触发全局未登录事件。
- frontend 调整认证跳转，认证上下文监听全局未登录事件后清空 user 并跳转 `/login`。

## Test Plan

- 运行 `pnpm typecheck` 和 `pnpm build`。
- 验证登录、注册、`/api/auth/me`、会话列表、会话详情、创建会话、删除会话、登出都返回统一 envelope。
- 验证 `/api/chat` 登录后仍能正常流式输出 SSE，不被 JSON envelope 包裹。
- 验证未登录访问 `/api/conversations` 返回 HTTP 401 + `code=10001`。
- 验证登录密码错误返回 HTTP 401 + `code=10002`，停留在登录页并展示错误。
- 验证无效请求体返回 HTTP 400 + `code=40001`，字段错误位于 `data.errors`。
- 验证不存在的 conversation 返回 HTTP 404 + `code=40401`。

## Assumptions

- “所有接口”指所有普通 JSON REST 接口；`/api/chat` 成功 SSE 流保持现有事件协议。
- 错误 HTTP status 保留原语义，不改成全量 200。
- 未登录 code 固定为 `10001`。
